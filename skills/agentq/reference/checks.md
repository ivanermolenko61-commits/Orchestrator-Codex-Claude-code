# agentq — механические проверки (изоляция, доверенный источник)

Справка к SKILL.md. Читать при `NOTE` о проверках из `CR route`, красных проверках, `waive`.

- Конфиг — `.agents/agentq.json` **на базовом коммите задачи** (`git show base:…`): `{"checks": {"backend": [["ruff","check","."],["python","-m","pytest","-q","-p","no:cacheprovider"]], "frontend": [[…]]}, "check_image": "локальный-образ:тег" | {"backend":…,"frontend":…}, "check_timeout": 600}`. Рабочее дерево и кандидат конфиг не подменяют; коммиты задачи с правкой этого файла отклоняются. Конфиг нужно закоммитить ДО `start`.
- Исполнение: `docker run` без сети, без секретов (только HOME, CI), `--read-only`, `--cap-drop ALL`, `no-new-privileges`, лимиты pid/памяти/CPU, пользователь 65534, исходники — точный коммит (`read-tree`+`checkout-index`, без .git, export-ignore и ссылок) монтируются read-only и копируются в tmpfs; образ берётся из локальных (`--pull never`, закрепляется по ID). Код возврата и вывод читает хост; результат (SHA, образ, команды, коды) пишет хост в `.ai/`, кандидат до него не дотягивается.
- Проверки идут до платного ревью: красные у кандидата возвращаются автору, ревью не запускается.
- База: красная команда перезапускается на базе. Красная только у кандидата → регрессия, возврат автору. Красная и на базе → `ok=None` (уже существующее падение): не вина кандидата, но и не подтверждение — нужна починка базы отдельной задачей или решение Ивана.
- Нехватка окружения (нет Docker/образа/проверок) — блокер ДО платного вызова с причиной; состояние сохраняется. Для неприменимых проверок: `CR waive <uid> "<причина ≥20 символов>"` — только если `checks` для этой роли в доверенной конфигурации нет; причина идёт reviewer-у, в отчёт и журнал.
- Остаточный риск: код кандидата в контейнере может сам завершиться с кодом 0 или подделать вывод тестового раннера — проверки это свидетельство для ревью diff, не доказательство; защита — независимое ревью, неизменность конфига/образа и запрет удаления тестов.
- Результат проверок — только то, что запустил доверенный код на точном SHA в контейнере; текст агента «тесты прошли» доказательством не считается.

## Быстрые проверки и авто-контекст (1.6.0)
- **Выборка.** Для команд `python -m unittest discover -s DIR [-p PAT]` и `node --test <пути/маски>` (единственная команда в `checks.<роль>`) движок строит карту «тест → файлы, от которых он зависит» по **базовому коммиту** (статические `import`; динамические импорты не видны) и в круге запускает только тесты, затронутые правкой, плюс новые и изменённые тесты единицы. Любое неизвестное — полный прогон: удаление файла, изменение вне кода, вспомогательный файл каталога тестов (conftest, фикстуры), существующий файл без теста-потребителя, пустая выборка, выборка ≥80% тестовых файлов, нераспознанная форма команды (причина — в `check_runs` и в `CR report`).
- **Что значит зелёная выборка.** Это НЕ проверка SHA: в запросе reviewer она названа «частичными проверками». `finish` и `integrate` требуют зелёного **полного** прогона на точном SHA; он выполняется один раз перед засчитыванием PASS (`ensure_full`). Красная выборка = красные проверки кандидата (сверяется с базой только по тестам, которые на базе есть; красная и там — полный прогон решает).
- **partial_miss.** Выборка зелёная, ревью PASS, полный прогон красный → PASS не засчитан, красный круг автору, причина вызова автора `partial_miss`; частота — в `CR report` («проверки <uid>: …»).
- **`--fast`.** При зелёной выборке полный прогон идёт параллельно ревью; красный полный прогон отбрасывает вердикт PASS (причина `fast_discarded`), вызов ревью остаётся в учёте. На каждом кандидате с зелёной выборкой полный прогон выполняется (в обычном режиме — один на принятую единицу).
- **Выключатели (для диагностики).** `AGENTQ_PARTIAL=0` — только полные прогоны (как 1.5.1); `AGENTQ_AUTOCTX=0` — без авто-контекста.
- **Авто-контекст автору.** К файлам единицы и ручному `--context` движок добавляет подписи без тел (python: def/class; js/ts: export) в порядке: файлы, которые ИМПОРТИРУЕТ единица (imports) → пути из цели, контракта, спецификации (named) → соседние файлы каталога (siblings) → вызывающие (importers); ≤6 файлов, ≤8 КБ, защищённые зоны, секретные пути и похожее на секрет не передаются. В записи вызова автора `auto_context` хранит путь, sha256, источники и режим `signature`: по нему видно, откуда пришёл файл (только `named` — доказательство «путь написал тимлид», а не работы авто-контекста).
