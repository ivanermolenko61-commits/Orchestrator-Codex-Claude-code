# agentq — сбои, восстановление, контекст, время

Справка к SKILL.md. Читать при коде 2 (сбой/таймаут/ответ не по схеме) и при вопросах о контексте участников.

## Сбой вызова и восстановление
- Ответ привязан к точному запросу (receipt). После сбоя `CR cycle`/`review` снова: готовый ответ читается без нового вызова; без ответа — блокер, повтор запрещён. Новый id, новая цель или новый коммит для обхода учёта не работают.
- **Единственный автоповтор (1.5.0)** — только для вызова, который достоверно не начался: процесс завершился с кодом ≠0, в выводе нет ничего, кроме служебных событий до обращения к модели (`thread.started`, `error`), а stderr — временный отказ (429, разрыв сети, 503) без признаков исчерпанной квоты. Повтор один, после паузы (`AGENTQ_RETRY_PAUSE`, по умолчанию 20 с), в том же резерве бюджета; записан в `retry.json` каталога вызова. Таймаут, прерывание, любой иной вывод или текст ошибки, квота (`usage limit`) — неопределённый исход: повтора нет.
- Вызов привязан к снимку (`subject`: SHA и режим). Сохранённый запрос (его хэш сверяется с записью резерва) и receipt используются как есть, поэтому изменение контекста после сбоя им не мешает и новый запрос не строится; ответ не принимается для другого снимка. Receipt и резерв версии 1.2.0 (нет `subject`) читаются по сохранённому запросу, если он целиком соответствует receipt и содержит тот же диапазон SHA.
- Свидетельства (запросы, ответы, события, отчёты) лежат в `.ai/task/calls/`; полный отчёт ревью — в `.ai/reviews/` (вывод команды по умолчанию сжатый, полный — `--verbose`).

## Контекст автора и reviewer
- `unit … --context F…` (до 6 файлов, ≤40000 байт каждый) и спецификация единицы — единственный канал контекста. Автор получает файлы из своей рабочей копии (её HEAD), reviewer — из проверяемого коммита; оба — как «данные только для чтения» с путём и `sha256` и строкой «Редакция требований». Что видели участники, записано в `calls.<вызов>.context` и в вердикте.
- Reviewer получает diff с контекстом целой изменённой функции (`git diff -W`); если он не помещается в лимиты — прежний узкий контекст (`-U3`, фронтенд `-U15`).
- Порядок запроса ревью: сначала неизменное между кругами (роль, правила, формат, цель, контракт, требования, контекст), затем текущий круг (раунд, SHA, проверки, замечания) и diff — общий префикс запросов совпадает, сервис может взять его из кэша (видно по «из кэша» в `CR report`).
- Секрет, защищённая зона/конфиг, секретный путь, ссылка/подмодуль, не-UTF-8, лишний размер, файл, исчезнувший в снимке, — отказ до резерва и вызова модели.
- Свежесть: изменённый после PASS контекст — значимое изменение: backend — `finish` и `status` называют изменившиеся файлы, приёмка не подтверждается, `review` идёт в полном режиме; frontend — `integrate` отказывает, если итоговое дерево отличается по файлам контекста; изменение после интеграции — `finish` не подтверждает приёмку и называет решение Ивана. При `--continues` прежний PASS переносится только при той же цели, контракте, спецификации и составе `--context`.

## Время этапов
- Только измерение: на качество, бюджеты, recovery не влияет. События (`start`/`end`/`recovered`) пишутся в `.ai/task/timing/<uid>.jsonl` по монотонным часам: вызов (исход ok/error/aborted, длительность, байты, токены), проверки, ожидание `--after`.
- `status`/`finish` показывают сводку по этапам, сумму длительностей и календарный охват (при параллельной работе сумма больше — это не elapsed); оборванные вызовы — «без известной длительности», не ноль. Не измеряются работа тимлида между командами, подготовка запросов, git, ожидание решений Ивана. Процент ускорения без сопоставимых прогонов не заявляется.
