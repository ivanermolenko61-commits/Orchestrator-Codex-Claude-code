# agentq — выбор модели и усилия Claude (1.4.0)

Справка к SKILL.md. Читать перед `--complexity`/`--risk`/`--model`, при отказе `MODEL:` и вопросах о профиле.

Выбор идёт отдельно для каждой роли и единицы **таблицей правил в движке, без модельного вызова**: признаки задаёт тимлид (`--complexity`, `--risk`), движок добавляет признаки риска по файлам и применяет профиль. Codex не затрагивается: модель `gpt-6.1-sol` фиксирована, меняется только его effort (`low` простое, `medium` обычно, `high` с причиной; без авто-повышения и fallback).

| Класс (`--complexity`) | Автор Claude | Reviewer Claude |
|---|---|---|
| `mechanical` — ограниченная механическая правка, поиск и извлечение фактов | haiku/low | sonnet/low |
| `matching` — нужно сопоставление | haiku/medium | sonnet/low |
| `standard` (по умолчанию) — реализация по ясному контракту, обычное ревью | sonnet/medium | sonnet/medium |
| `complex` — сложная локальная диагностика | sonnet/high | sonnet/high |
| `architectural` — архитектурная неопределённость, межмодульные связи | opus/medium | opus/medium |
| высокий риск: `--risk high`, либо движок видит защищённую зону / единицу protected / правку самого agentq | opus/high | opus/high |

Haiku — не финальная приёмка исполняемой логики: Claude-reviewer никогда не бывает Haiku, ни по политике, ни вручную (отказ и с `--reason`). Классифицировать только по длине запроса или числу файлов нельзя; признаки движка риск повышают, признак координатора `normal` их не снимает.

## Команды
- `CR profile <uid> author|review [--complexity C] [--risk R] [--model M] [--effort E] [--reason …] [--applied …]` — **предпросмотр** без вызова модели: журнал не меняет (сохраняются только признаки в единице и сообщённое `--applied`). Фактический запуск (`review`/`cycle`/`author-claude`) сам пишет выбранный профиль, источник и причину в запись резерва вызова до обращения к модели.
- `CR review|cycle … [low|medium|high] [--model haiku|sonnet|opus] [--complexity …] [--risk …] [--reason …]` — для Claude-reviewer выбранный профиль реально попадает в argv (`--model`, `--effort`). Явный effort прежнего вида меняет только усилие.
- **Ручной override** (`--model`/effort) имеет приоритет над политикой, пишется в журнал как `override` с причиной. Недоступную комбинацию не подменяет: отказ.

## Автор Claude (`author-claude`, `cycle --task-file`)
- `CR author-claude <uid> --task-file F [--complexity …] [--risk …] [--model …] [--effort …]` запускает `claude -p` с профилем по политике для **backend-единицы со списком файлов** (protected/клиентские файлы и секретные пути отказаны до вызова).
- Изоляция: автор работает во **временной копии вне репозитория** — только файлы единицы из коммита и проверенный контекст; `--tools Read,Edit,Write` (без Grep, Glob, Bash и сети), режим `dontAsk`. Внутри рабочего каталога `dontAsk` чтение разрешает и без правила `allow` (проверено вживую), поэтому граница чтения — изоляция копии, а allow/deny — второй слой. Файл с похожим на секрет не передаётся.
- После процесса копия файлов и хеши сохраняются в каталог вызова до удаления временной копии; неуспешный процесс оставляет правки в `failed-result/` для разбора, они не применяются. Доверенный код отклоняет лишние файлы, изменение контекста, удаление, пустую правку, секрет, скрытые символы, не-UTF-8, подмену модели.
- Иначе файлы переносятся в рабочую копию агента `<AQ_WORKTREES>/<repo>-aq-<задача>-<uid>` (ветка `agent/claude/<задача>-<uid>`), коммит — кандидат (`agent-claude`, только файлы единицы, `check_diff`). Дерево, индекс и ветка пользователя не читаются и не меняются. Любое постороннее изменение рабочей копии агента — отказ до нового вызова. Перенос идемпотентен.
- Дальше — `CR review <uid>` (Codex, на SHA кандидата, с проверками) и `CR integrate <uid>`. `CR cycle <uid> --task-file F` гоняет круг «автор Claude → проверки → ревью Codex → исправление» с контрольными точками и остановкой без прогресса. Зависимость `--after` от такой единицы готова только после её `integrate`.
- Основной интерактивный чат тимлида и coder-субагента движок не переключает: `profile … author` выдаёт параметры, применение в журнале — «сообщено» (`--applied`), не «подтверждено». Версия `claude` из PATH может быть старше среды текущей сессии (2026-11-09: headless 2.1.286 даёт `haiku` = `claude-haiku-4-5`); Haiku через `author-claude` на 2.1.286 недоступен по версии, вживую не проверен.

## CLI, окружение, журнал
- Версия `claude --version` сверяется с минимальной для актуальной модели алиаса (haiku 2.1.293, sonnet 2.1.284, opus 2.1.280). Недоступная ступень заменяется ближайшей **выше** с записью причины; версия не определена — отказ. Окружение очищается (`CLAUDE_CODE_EFFORT_LEVEL`, `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_*_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, ключи), настройки пользователя и проекта не читаются, `--fallback-model` не задаётся.
- Фактическая модель — из `modelUsage`: каждая модель ответа должна быть запрошенного семейства и поколения не ниже 5, иначе ответ не принимается (`MODEL:`), вызов израсходован, автоповтор запрещён. Фактическое усилие CLI не сообщает — в журнале оно «запрошено».
- Повышения профиля после неудачи нет: если тимлид видит нехватку качества, он сам задаёт следующий вызов с override и причиной. Лимиты не меняются; сеть, квота и нехватка контекста повышением модели не лечатся.
- Журнал: запрошенный профиль — в записи резерва вызова, фактическая модель, токены и цена по прейскуранту (не счёт подписки) — в журнале времени; `CR status`/`CR report` показывают всё. Экономию без сопоставимых измерений не заявлять.
