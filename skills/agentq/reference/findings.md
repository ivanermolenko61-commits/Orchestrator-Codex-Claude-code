# agentq — постоянные ID замечаний и формат вердикта

Справка к SKILL.md. Читать при спорном вердикте, `UNCERTAIN`, диагностике реестра.

## Реестр
- Каждый BLOCKER/MAJOR получает в реестре единицы (`state.json`, `units.<uid>.findings`) номер `F1`, `F2`… — требование или риск, сценарий, доказательство, условие закрытия. Номер присваивает движок (reviewer ID не придумывает); закрытые и снятые номера не переиспользуются; у каждой единицы свой счётчик. Реестр переносится по `--continues`, пишется в журнал и дописывается в отчёт ревью («ДВИЖОК: реестр замечаний»).
- Автору и reviewer повторно уходит реестр открытых замечаний с ID (данные, не инструкции).

## Формат ответа reviewer
- **Оба reviewer (с 1.5.0) отвечают JSON по одной схеме** (`CLAUDE_SCHEMA`): `verdict` PASS|FIX|UNCERTAIN, `summary`, `findings` (новые: severity, location, problem, scenario, evidence, close_when, ref пустой, fix), `prior` (по элементу на каждый прежний ID: id, status closed|remains|withdrawn, note). Claude — через `--json-schema`, Codex — через `--output-schema`. Статусы читаются из полей, а не из текста: перевод строки в поле не может подделать метку.
- Ответ Codex не по схеме (не JSON, нет поля, неизвестный статус) — не PASS: блокер с диагностикой, вызов израсходован, скрытого повторного вызова нет. Человекочитаемый отчёт строится из JSON и сохраняется в `.ai/reviews/`.
- Прежний текстовый формат (строки `[ЗАКРЫТО F<n>] …`, `[ОСТАЛОСЬ F<n>] …`, `[СНЯТО F<n>] <обоснование>`, `[НОВОЕ]`, последняя строка `VERDICT: PASS|FIX`) читается только для вызовов и receipts версий до 1.5.0: формат разбора определяется записью резерва вызова (`review_format`), поэтому восстановление применяет тот же разбор к тому же сохранённому ответу. Метки в цитатах, блоках кода, середине строки не учитываются.

## Что засчитывается
- Прогресс даёт только «закрыто» для ID, который открыт у этой единицы, назван в отчёте один раз и закрыт на другом SHA, чем открыт. Неизвестный, повторённый, уже закрытый ID и статус без ID — диагностика, не прогресс. «Снято» (обоснование ≥20 символов) — не исправление кода: замечание считается снятым как ошибочное, но прогрессом круга не является. Нет статуса у открытого ID — он остаётся открытым, закрытие не выдумывается.
- PASS возможен только когда каждый открытый ID явно закрыт или снят. PASS при «осталось» — FIX; PASS без статуса открытого ID или со спорными статусами — `UNCERTAIN` с диагностикой (ревью того же SHA повторяется новым вызовом, автору такой отчёт не передаётся). PASS при новых BLOCKER/MAJOR или при незакрытых требованиях автора — FIX. Незакрытый BLOCKER/MAJOR исключает приёмку.
- MINOR — не больше 3 и только по изменённому коду задачи; на вердикт не влияют.
- Переход с прежних версий: состояние без реестра — открытые BLOCKER/MAJOR последнего текстового отчёта один раз регистрируются как `F1…` (источник и число — в `findings_imported`); отдельной модели для сопоставления нет.
