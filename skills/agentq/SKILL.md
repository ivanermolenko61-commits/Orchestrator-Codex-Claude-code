# agentq — Codex + Qwen

Тимлид — текущий чат VS Code. В Codex укажи `--lead codex`, в Qwen — `--lead qwen`. Claude на паузе: не запускай его, не назначай автором/reviewer. Настройки и история Claude сохраняются.

Точка входа после установки:

```text
"{{PYTHON}}" "{{ENGINE}}" --lead codex <команда>
"{{PYTHON}}" "{{ENGINE}}" --lead qwen <команда>
```

В PowerShell перед первым кавычкованным путём нужен `&`. В исходной рабочей копии: `python skills/agentq/agentq_global.py --lead codex ...` (либо qwen).

## Порядок работы

1. Прочитай AGENTS.md проекта и навык agentq-teamlead из базы знаний. Выполни `route`. При проектном координаторе используй его инструкции; второй цикл не запускай. Ошибка маршрута — блокер, скрытая подмена сервиса запрещена.
2. При продолжении сначала `status --json`. Одно состояние `.ai/` хранит цель, назначения, кандидаты, бюджет, замечания, проверки и следующий шаг. Смена чата меняет координатора; author/reviewer существующих единиц сохраняются.
3. Небольшую связную задачу реализуй сам: `start "цель" --author <текущий сервис>`; коммит правок; `review main`. Дополнительный фоновый вызов автора не нужен. Проверяет другой сервис.
4. Для нескольких частей: `start "цель" --kind mixed --author <сервис> --contract-file <файл>`; затем `unit <uid> --kind backend|frontend|protected --author codex|qwen --files ... [--context ...] [--after ...] [--spec-file ...]`. Категория определяет проверки, сервис выбирается по контексту и владению файлами. Оба сервиса могут писать любой язык. Автор по умолчанию наследуется от start.
5. Делегированная единица: `cycle <uid>` → `integrate <uid>`. Оба автора выдают JSON с полным содержимым разрешённых файлов; проверку и запись делает движок. Защищённые единицы реализует текущий тимлид непосредственно, затем `review <uid>`; ограничение одинаково для обоих сервисов.
6. Независимые единицы выполняй параллельно, максимум два исполнителя. Пересечения файлов запрещены. Зависимые изменения — последовательно через `--after`, после интеграции зависимости. Общий контракт и итоговую совместимость проверяй при интеграции.
7. FIX возвращай закреплённому автору с актуальными ID и условием закрытия. UNCERTAIN/обрыв не превращай в PASS и не повторяй неопределённый вызов. Читай reference/recovery.md и reference/budget.md при остановке; `rethink` — один пересмотр подхода после остановки без прогресса.
8. `finish` закрывает только принятую работу; `report` показывает расход каждого сервиса. Итог требует PASS точного SHA и полного прогона проверок либо обоснованного `waive`, когда проверок в доверенной конфигурации нет. Выборочные проверки внутри цикла и полный прогон при приёмке сохраняются.

## Контекст и расход

- Передавай цель, контракт, файлы единицы, необходимые зависимости и открытые замечания. Полные журналы читай для диагностики, компактный status — для продолжения. Не сокращай необходимый контекст ради экономии.
- Codex: gpt-6.1-sol, Qwen: qwen4-max; effort по умолчанию high. Автоматической смены модели/понижения effort нет. Фоновый Qwen использует подписочный вход, безопасный режим и только служебный structured_output.
- Бюджет и receipts общие для цепочки; новый чат их не сбрасывает. Неизвестные показатели токенов остаются неизвестными. Отчёт учитывает фоновые вызовы движка; расход интерактивного тимлида в них не входит.
- Исторические задачи доступны в status/report. Для продолжения новой парой: `finish --abandon`, затем `start ... --continues <старый id> --author ...`. Расход и замечания сохраняются; старый PASS при смене назначений не переносится. Историю не переименовывай.
- Не обходи protected, бюджет, блокировки, секреты и проверки. При недоступности одного сервиса работа останавливается; саморевью и fallback запрещены.

Публикация и обновление рабочей установки — по правилам AGENTS.md проекта. Наличие файлов CLI ещё не доказывает авторизацию и успешный живой запуск.
