# /agentq — Codex пишет фронтенд, Claude пишет бэкенд, код ревьюит другой сервис

`CR` = `bash ~/.claude/skills/agentq/codex-review.sh <команда>`. Состояние — `<репо>/.ai/` (вне git), переживает закрытие чата. Справка — `~/.claude/skills/agentq/reference/` (читать только по ссылке ниже или из сообщения движка).

Задача: $ARGUMENTS

## Роли
| Часть | Автор | Reviewer |
|---|---|---|
| Фронтенд, клиентские тесты | Codex (`gpt-6.1-sol`, без инструментов, ответ JSON) | Claude (профиль по политике, отдельный процесс без инструментов) |
| Бэкенд, серверные тесты | Claude Code (тимлид, один coder или `author-claude`) | Codex (read-only, без личного конфига и инструментов, вердикт JSON) |
| Защищённые зоны, миграции, CI, права, платежи, сам agentq | Claude Code | Codex |
| Постановка, контракт, интеграция, итог | тимлид | — |

Недоступность сервиса — блокер маршрута: подмены автора или reviewer нет, «Claude пишет всё» не включается. Gemini/OpenCode в схему не входят.

## Шаг 0. Маршрут (первым, без моделей)
`CR route` →
- **10** — у проекта свой координатор: действуй по его `.claude/commands/agentq-codegen.md` и `docs/agentq.md`; `CR start/cycle/review` не запускать.
- **12** — координатор без перекрёстных маршрутов: назови недостающее, остановись, реши с Иваном.
- **11** — маршрут не готов: покажи `MISSING:` и остановись.
- **0** — готов. `NOTE:` показывай Ивану (нет карточки проекта → создать по шаблону; нет `checks`+`check_image` в `.agents/agentq.json`, закоммиченных до задачи → приёмка только через `waive`, см. reference/checks.md).
- `MODE=учебный` — сначала план и «да» Ивана, потом `start --plan-approved`; код целиком не пиши, предложи часть Ивану.

## Шаг 1. Постановка
1. Нет задачи — `CR status`: есть активная — продолжай; нет — спроси. Не git — остановись. Ветка `main`/`master` — создай `aq/<коротко>`.
2. Раздели по ролям: клиент (`frontend/`, `client/`, `web/`, `ui/`, `*.tsx|jsx|vue|svelte|css|html`) — Codex, сервер (`backend/`, `server/`, `api/`, `*.py`) — Claude; иначе маски `.agents/agentq.json`. Защищённые зоны — единица `protected`.
3. Смешанная: контракт (поля, типы, ошибки, права, сбои) в файл ≤4000 символов → `CR start "<цель>" --kind mixed --contract-file F [--estimate N]` → `CR unit <uid> --kind backend|frontend|protected --files … [--context …] [--spec-file …]` (до 8 файлов, без пересечений; `--after <uid>` — зависимость). Контракт меняется только с новым ревью затронутых единиц.
4. Серверная: `CR start "<цель>"` (единица `main`). Клиентская: `start --kind mixed` + краткий контракт + frontend-единица.
5. `--estimate N` — начальная оценка обращений (не лимит, превышение показывает `CR report`). Бюджет — reference/budget.md.
6. Независимые единицы — параллельно: `CR cycle fe` в фоне, пока ведёшь backend. Зависимой — `--after be` и `cycle fe --wait СЕК` (без `--wait` — код 5). Одна команда на единицу (иначе 4 BUSY).

## Шаг 2. Бэкенд и protected (автор Claude → Codex)
- Реализуй сам (или одним coder с точным контрактом) в ветке `aq/…`, прогони тесты, закоммить только файлы задачи (`git add <файлы>`) → `CR review [uid] [low|medium|high]` (`high` — данные/авторизация/оплата/миграции). Ревью привязано к SHA; правка файлов после PASS (включая скрытые от модели секретные и lock-пути) снимает приёмку.
- Для backend-единицы со списком файлов можно отдать авторство headless-автору Claude: `CR cycle <uid> --task-file F [--complexity …] [--risk …]` (изолированная копия, проверки, ревью Codex, исправления), затем `CR integrate <uid>`. Protected — только тимлид.
- Клиентский код в backend-единице отклоняется (`РОЛЬ:`) — оформи frontend-единицу. Профиль Claude — reference/model-policy.md.

## Шаг 3. Фронтенд (автор Codex → Claude)
`CR cycle <uid> [effort]` делает всё сам: Codex пишет файлы → доверенный код проверяет пути, зоны, секреты, скрытые символы, удаление тестов → коммит в `agent-worktrees/<проект>-aq-<id>-<uid>` → проверки точного SHA в контейнере (красные — автору, ревью не зовётся) → Claude-reviewer → замечания с ID автору → до PASS или остановки. После PASS и зелёных проверок — `CR integrate <uid>` (ff-only или слияние без конфликтов с проверками итогового SHA; изменённые файлы единицы — новый base и ревью). Вручную между сервисами ничего не переносится.

## Коды выхода
- `0` PASS. `1` FIX — исправь BLOCKER/MAJOR (спорное не исправляй молча, укажи в итоге), коммит, снова `review` (в `cycle` — само).
- `2` блокер: сбой, таймаут, ответ не по схеме — вызов израсходован, повтора нет (кроме одного автоповтора не начавшегося вызова); назови причину → reference/recovery.md.
- `3` LIMIT/СТОП — контрольная точка без прогресса, два круга без прогресса или предел Ивана: не проси «ещё вызов», разбери причину, `CR rethink <uid> "<причина и подход>"` или решение Ивана → reference/budget.md.
- `4` BUSY, `5` WAIT (зависимость не готова).
- Вывод ревью сжатый: вердикт, открытые ID, путь к полному отчёту (`--verbose` — полностью). Спорный вердикт, UNCERTAIN → reference/findings.md.

## Итог
`CR finish` (приёмка: PASS + проверки на точном SHA, иначе «НЕ ПОДТВЕРЖДЕНА», закрыть без приёмки — только `--abandon`) и `CR report`. Отчёт Ивану: что сделано, автор и reviewer по единицам, SHA, проверки, вердикты и круги, расход (вызовы, токены, превышение оценки), блокеры, ветки. Не «PASS по тимлиду» и не саморевью.

## Запрещено
- `git push`, деплой, миграции прод-БД — только по явной команде пользователя.
- Запускать Codex с инструментами, менять параметры его запуска, подменять модель; писать клиентский код вместо Codex; повторять вызов после неопределённого исхода; второй цикл поверх проектного координатора; править файлы автора в основном дереве.
- Правки reviewer — авторские, их проверяет другой сервис.

Справка: budget.md (бюджет, остановки, учёт расхода), findings.md (ID замечаний, формат вердикта), recovery.md (сбои, контекст, время), checks.md (проверки), model-policy.md (профили Claude, author-claude), prompting.md (только для ассистента в чате, готовящего поручения).
