# Orchestrator Codex + Claude Code — agentq v1

Установка принятого глобального /agentq на другой компьютер. Claude Code — тимлид и автор бэкенда; Codex — автор фронтенда. Независимое ревью выполняет другой сервис, проверки идут в Docker.

## Требования

Целевая среда v1: Windows, NTFS, Git Bash. Нужны:
- Git и Python 3.9+ (команда py -3, python3 или python);
- установленные Codex CLI и Claude Code CLI с отдельным входом в аккаунты на этом компьютере;
- Docker Desktop с Linux-контейнерами; локальный образ проверок для каждого проекта.

Установка этого пакета не устанавливает сторонние программы, не переносит входы в аккаунты и не запускает модельные запросы. Доступ к закрытым проектам и их зависимости настраиваются на каждом компьютере отдельно.

## Установка на втором компьютере

Открыть **Git Bash**:

```bash
git clone https://github.com/ivanermolenko61-commits/Orchestrator-Codex-Claude-code.git
cd Orchestrator-Codex-Claude-code
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Последняя команда должна вывести: «Установленные копии совпадают с репозиторием».

Установщик кладёт файлы в ~/.claude: навык agentq, общие правила, роли и agentsrules.py. Прежние версии изменяемых файлов, включая ~/.claude/CLAUDE.md, сохраняет в ~/.claude/backups/install-ДАТА-ВРЕМЯ/. Прочие файлы не удаляет. Для одного лишь просмотра отличий запускать без --apply.

После установки открыть **новую сессию Claude Code** в целевом проекте:

```text
/agentq <цель задачи>
```

Продолжение прерванной задачи: /agentq без аргументов.

## Готовность проекта

Из корня Git-проекта в Git Bash:

```bash
bash ~/.claude/skills/agentq/codex-review.sh route
```

Коды: 0 — глобальный маршрут готов; 10 — использовать собственный координатор проекта; 11 — не хватает окружения; 12 — старый проектный координатор. Команда показывает причину и не обращается к модели.

Настроить AGENTS.md по ~/.claude/workflow/project-template.md. Конфигурацию .agents/agentq.json закоммитить **до** начала задачи. Пример для проекта с pytest (образ должен уже содержать Python и зависимости этого проекта):

```json
{
  "checks": {
    "backend": [["python", "-m", "pytest", "-q", "-p", "no:cacheprovider"]]
  },
  "check_image": {"backend": "my-project-checks:1"},
  "check_timeout": 600
}
```

Для frontend добавить реальные команды и образ проекта. Не копировать чужие имена образов без их подготовки. Отсутствие Docker, образа или подходящих проверок — явный блокер, а не успешная приёмка.

Для рабочих копий по умолчанию используется C:/Projects/agent-worktrees. Другой путь можно задать переменной AQ_WORKTREES в окружении сессии. Для нестандартного размещения CLI предусмотрены CODEX_BIN и CLAUDE_BIN (см. движок). Пути проектов v1 должны быть ASCII.

## Проверки без моделей

После установки:

```bash
bash scripts/test-install-global.sh
py -3 skills/agentq/selftest.py
```

Selftest использует поддельные CLI и временные Git-проекты; живых модельных запросов нет. Он требует установленный ~/.claude/scripts/agentsrules.py. На среде с python3 вместо Windows launcher заменить py -3 на python3. Прогон на Linux не подтверждает совместимость экспорта с файловыми системами за пределами NTFS.

## Обновление и восстановление

```bash
git pull --ff-only
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Затем открыть новую сессию Claude Code. При расхождении истории Git остановиться и разобраться с локальными изменениями; не использовать reset/clean для автоматического обновления.

Для восстановления брать нужные прежние файлы из указанной установщиком папки backups и возвращать их по тем же относительным путям внутри ~/.claude. Переустановка не переносит состояние задач: оно остаётся в .ai целевого проекта на исходном компьютере.

## Что включено и что не переносится

Включены движок, selftest, точка входа, SKILL.md, общие защищённые зоны, три описания ролей, шаблон карточки проекта и установщик. Основной движок и его selftest перенесены без изменения байтов.

Не включены личная база знаний, .ai, журналы запросов, токены, учётные данные, .env, проектные базы и Docker-образы. Глобальный CLAUDE.md и шаблон проекта в этом пакете — общие инструкции без локальной базы знаний владельца. После установки можно добавить собственные инструкции; проверка установщика покажет отличие от пакета.

## Происхождение и границы приёмки

Исходный выпуск: ivanermolenko61-commits/ai-knowledge, main 68b1d9488d0137223feac7b8ff860a09fe6c3d5f.
Код движка принят на 0862098: по сохранённому отчёту автора независимый Codex PASS (17-й вызов), selftest 181/181.
Манифест package-manifest.json фиксирует исходные Git blob SHA и контрольные суммы файлов.

Новый пакет проверяется установкой в отдельную папку и офлайн-selftest. Это упаковка принятого кода, а не новый независимый аудит всего репозитория.

Ограничения v1: ASCII-пути, NTFS, экспорт в новый каталог, максимум 300 МиБ и 20 000 файлов. Docker считается доверенной границей. Код кандидата в контейнере способен подделать результат раннера; зелёные проверки служат свидетельством вместе с независимым ревью. Сохраняется граница одного пользователя. Публикация кода не означает передачи входа в аккаунты или гарантии наличия конкретной модели в другом аккаунте.

## Источник изменений

Код v1 происходит из ai-knowledge; этот репозиторий — устанавливаемая поставка. Обновления движка переносить только из принятого исходного коммита с обновлением манифеста. Локальные исправления копий в ~/.claude не считать обновлением источника.
