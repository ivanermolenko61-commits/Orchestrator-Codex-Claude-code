# Orchestrator Codex + Claude Code — agentq 1.5.1

**Единственный источник оркестратора agentq**: движок, навык, роли, общие защищённые зоны и установщик развиваются и устанавливаются из этого репозитория на любом компьютере. База знаний ai-knowledge хранит только личные правила и контекст и не копирует, не обновляет и не откатывает эти файлы.

Установка принятого глобального /agentq. Claude Code — тимлид и автор бэкенда; Codex — автор фронтенда. Независимое ревью выполняет другой сервис, проверки идут в Docker.

## Требования

Целевая среда v1: Windows, NTFS, Git Bash. Нужны:
- Git и Python 3.9+ (команда py -3, python3 или python);
- установленные Codex CLI и Claude Code CLI с отдельным входом в аккаунты на этом компьютере;
- Docker Desktop с Linux-контейнерами; локальный образ проверок для каждого проекта.

Установка этого пакета не устанавливает сторонние программы, не переносит входы в аккаунты и не запускает модельные запросы. Доступ к закрытым проектам и их зависимости настраиваются на каждом компьютере отдельно.

## Установка

Открыть **Git Bash**:

```bash
git clone https://github.com/ivanermolenko61-commits/Orchestrator-Codex-Claude-code.git
cd Orchestrator-Codex-Claude-code
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Последняя команда должна вывести: «Установленные копии совпадают с репозиторием».

Если на компьютере уже есть личный `~/.claude/CLAUDE.md` и собственный `workflow/project-template.md` (например, из ai-knowledge), добавить `--core-only` в обе команды: тогда ставится только оркестратор, а личные инструкции не сравниваются и не перезаписываются.

```bash
bash scripts/install-global.sh --apply --core-only
bash scripts/install-global.sh --core-only
```

Установщик кладёт файлы в ~/.claude: навык agentq (вместе с файлом VERSION), общие правила, роли и agentsrules.py. Прежние версии изменяемых файлов, включая ~/.claude/CLAUDE.md, сохраняет в ~/.claude/backups/install-ДАТА-ВРЕМЯ/. Прочие файлы не удаляет. Для одного лишь просмотра отличий запускать без --apply.

После установки открыть **новую сессию Claude Code** в целевом проекте:

```text
/agentq <цель задачи>
```

Продолжение прерванной задачи: /agentq без аргументов.

## Готовность проекта

Из корня Git-проекта в Git Bash:

```bash
bash ~/.claude/skills/agentq/codex-review.sh route
```

Коды: 0 — глобальный маршрут готов; 10 — использовать собственный координатор проекта; 11 — не хватает окружения; 12 — старый проектный координатор. Команда показывает причину и не обращается к модели.

Настроить AGENTS.md по ~/.claude/workflow/project-template.md. Конфигурацию .agents/agentq.json закоммитить **до** начала задачи. Пример для проекта с pytest (образ должен уже содержать Python и зависимости этого проекта):

```json
{
  "checks": {
    "backend": [["python", "-m", "pytest", "-q", "-p", "no:cacheprovider"]]
  },
  "check_image": {"backend": "my-project-checks:1"},
  "check_timeout": 600
}
```

Для frontend добавить реальные команды и образ проекта. Не копировать чужие имена образов без их подготовки. Отсутствие Docker, образа или подходящих проверок — явный блокер, а не успешная приёмка.

Для рабочих копий по умолчанию используется C:/Projects/agent-worktrees. Другой путь можно задать переменной AQ_WORKTREES в окружении сессии. Для нестандартного размещения CLI предусмотрены CODEX_BIN и CLAUDE_BIN (см. движок). Пути проектов v1 должны быть ASCII.

## Проверки без моделей

После установки:

```bash
bash scripts/test-install-global.sh
py -3 skills/agentq/selftest.py
```

Selftest использует поддельные CLI и временные Git-проекты; живых модельных запросов нет. Он требует установленный ~/.claude/scripts/agentsrules.py и ищет его через домашний каталог пользователя. Для проверки без затрагивания рабочей установки создать пустой каталог `<home>`, задать `HOME`/`USERPROFILE` на него и `CLAUDE_HOME=<home>/.claude`, выполнить `install-global.sh --apply --core-only` и запустить установленный `selftest.py` (на 1.4.0: 738/738; на 1.3.0: 387/387; на чистой 1.2.0: 301/301).

Целостность пакета проверяет `python scripts/manifest.py check` (она же входит в `test-install-global.sh`); после правки файлов — `python scripts/manifest.py write`. На среде с python3 вместо Windows launcher заменить py -3 на python3. Прогон на Linux не подтверждает совместимость экспорта с файловыми системами за пределами NTFS.

## Обновление и восстановление

```bash
git pull --ff-only
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Затем открыть новую сессию Claude Code. Установленную версию показывает `cat ~/.claude/skills/agentq/VERSION`. Если установленная версия новее версии клона, установщик отказывает (код 2) и ничего не меняет: сначала обновить клон. Осознанный откат: `AQ_ALLOW_DOWNGRADE=1`. При расхождении истории Git остановиться и разобраться с локальными изменениями; не использовать reset/clean для автоматического обновления.

Для восстановления брать нужные прежние файлы из указанной установщиком папки backups и возвращать их по тем же относительным путям внутри ~/.claude. Переустановка не переносит состояние задач: оно остаётся в .ai целевого проекта на исходном компьютере.

## Что включено и что не переносится

Включены движок, selftest, точка входа, SKILL.md и справка навыка `skills/agentq/reference/*.md`, общие защищённые зоны, три описания ролей, шаблон карточки проекта, установщик и скрипт манифеста. Движок, его selftest и точка входа перенесены из принятого выпуска без изменения байтов (git blob id зафиксированы в `package-manifest.json`, раздел provenance). При том переносе в SKILL.md изменены только две ссылки на файлы ai-knowledge; позднее навык менялся вместе с версиями, а в 1.5.0 сокращён до ядра, подробности перенесены в `skills/agentq/reference/*.md`.

Не включены личная база знаний, .ai, журналы запросов, токены, учётные данные, .env, проектные базы и Docker-образы. Глобальный CLAUDE.md и шаблон проекта в этом пакете — общие инструкции без локальной базы знаний владельца. После установки можно добавить собственные инструкции; проверка установщика покажет отличие от пакета.

## Происхождение и границы приёмки

Версия 1.1.0 содержит выпуск agentq из ai-knowledge, коммит 1171344235498ce6aae7a891d5d8867bce2636b1. Независимая приёмка движка: PASS на 9aca6cc (Codex gpt-6.1-sol high, вне движка); между 9aca6cc и 1171344 менялся только SKILL.md, исполняемый код идентичен. Самопроверка выпуска: 258/258 офлайн. Принятый неизменённый движок повторно на модельное ревью не отправляется.

Версия 1.1.1 меняет учёт бюджета: расход принадлежит конкретной задаче плана (цепочке `start`/`--continues`). Следующая задача после принятой начинается с нуля; незавершённую можно продолжить через `--continues` и после того, как владелец запустил другую самостоятельную задачу (`--new-work`), — прежде возвращение начиналось бы с нуля. Правило описано в SKILL.md («Область бюджета») и global/CLAUDE.md. Движок и selftest в 1.1.1 отличаются от принятого 9aca6cc (provenance: unchanged_from_source=false) и требуют собственной независимой приёмки; самопроверка 270/270.

Версия 1.2.0 вводит параллельную работу независимых частей (доработка существующей пары Claude + Codex, без новых платформ): (1) блокировка не на всю команду, а на единицу (`unit-<uid>`), структуру задачи (`start`/`unit`/`finish`), интеграцию и короткую транзакцию над `state.json`; `status` без блокировок; (2) прежняя проверка «любой `codex exec` блокирует вызов» убрана — осиротевший вызов своей единицы по-прежнему ловится по pid, повтор при неопределённом исходе запрещён; (3) `integrate` при ушедшей вперёд ветке (коммиты backend вне файлов единицы) строит слияние без конфликтов, проверяет итоговый SHA в контейнере до перемещения ветки и требует этих проверок при `finish`; (4) `state.json` сливается трёхсторонне по единицам и вызовам, резерв бюджета (предел, контрольные точки) атомарен; (5) `--after` ждёт готовности зависимости (`--wait`, код 5 WAIT, без расхода); frontend-зависимость должна быть влита. Исправлена найденная при проверках ошибка восстановления: сохранённый запрос сравнивался с учётом перевода строк (CRLF рабочей копии давал «другой запрос»). Движок и selftest отличаются от принятого 9aca6cc и требуют собственной независимой приёмки.

Версия 1.3.0 (первая итерация улучшения командной работы; кандидат, требует собственной независимой приёмки вне движка): (1) **согласованный контекст** — автор получает `--context`-файлы из HEAD своей рабочей копии, reviewer — из проверяемого коммита (не из рабочего дерева), оба как данные только для чтения с путём и sha256 и общей «редакцией требований»; секрет, защищённая зона, лишний размер, ссылка отклоняются до модели; восстановление использует сохранённый запрос и receipt (вызов привязан к снимку), изменение контекста после PASS отменяет приёмку backend до `finish` и блокирует слияние frontend при `integrate`; (2) **постоянные ID замечаний** — движок присваивает `F1…` каждому BLOCKER/MAJOR единицы, reviewer явно даёт статус каждого прежнего ID (закрыто / осталось / снято как ошибочное), прогресс засчитывается только за закрытый открытый ID этой единицы, неизвестный, повторённый, уже закрытый ID, метка без ID и метка в цитате прогресса не дают, PASS при незакрытом ID невозможен; реестр сохраняется при recovery, в журнале и в `--continues`, старые отчёты импортируются один раз; (3) **время этапов** — длительности автора, reviewer, проверок и ожидания `--after` по монотонным часам в `status`/`finish`, без двойного учёта при восстановлении, неизвестное не заменяется нулём, токены только по данным CLI. Бюджеты, receipts, recovery, защита от зацикливания и права ролей не менялись. Правила — в SKILL.md («Постоянные ID замечаний», «Контекст автора и reviewer», «Время этапов»).

Версия 1.4.0 (кандидат, требует собственной независимой приёмки вне движка): **автоматический выбор модели и усилия Claude** отдельно для автора и reviewer, без модельного вызова для классификации. Правила — таблица в движке (класс задачи `--complexity`, риск `--risk` плюс признаки риска по файлам: защищённая зона, единица protected, сам agentq); профиль Claude-reviewer реально передаётся в argv (`--model`, `--effort`) вместо прежнего жёсткого `opus`; автор Claude запускается движком реально: `CR author-claude` — `claude -p` с выбранным профилем для backend-единицы со списком файлов (инструменты без Bash, права только на файлы единицы; кандидат коммитится в отдельной рабочей копии агента на ветке `agent/claude/…`, как у автора Codex, — дерево и индекс пользователя не трогаются; в ветку задачи — только `integrate` после независимого PASS; `cycle <uid> --task-file F` для backend; восстановление после обрыва без нового вызова, обычные бюджеты и receipts); основной интерактивный чат и coder-субагента движок не переключает, для них `CR profile … author` выдаёт параметры, а применение помечается «сообщено тимлидом». Claude-reviewer никогда не бывает Haiku. Автор Claude работает во временной копии вне репозитория (только файлы единицы из коммита и проверенный контекст; репозиторий, индекс и секреты ему не видны; чтение вне копии CLI отклоняет — проверено вживую), результат сохраняется копией и хешами сразу после процесса, в рабочую копию агента его переносит доверенный код. `CR profile` — предпросмотр; запуск пишет профиль и причину в запись вызова. Ручной override (`--model`/effort) приоритетнее политики; недоступная в установленном CLI комбинация не подменяется молча (для политики — ближайшая ступень выше с записью причины, для ручного выбора — отказ); окружение процесса очищено от переменных, которые по документации приоритетнее флагов; фактическая модель сверяется с `modelUsage` ответа (все модели: семейство и поколение не ниже 5), несовпадение не принимается. Повышения профиля после неудачи нет (команды `escalate` нет): следующий профиль выбирает политика или ручной override, бюджеты, контрольные точки, `--max-calls` и остановка после кругов без прогресса не изменены; запрошенный профиль, причины, фактическая модель, токены по моделям и цена по прейскуранту видны в `CR status` и сохраняются при `--continues`; старые receipts читаются. **Не входит:** отчёт о расходе и причинах повторов, оценка обращений на задачу и JSON-вердикт Codex (решение 2026-11-09, `decisions/2026-11-09-agentq-review-and-budget.md` в ai-knowledge) в этой ветке не реализованы. Измерено живьём на CLI 2.1.286: алиас `haiku` даёт `claude-haiku-4-5`, `--effort` для него принят без ошибки и без следа в ответе (поэтому effort нигде не заявляется как подтверждённый, а haiku по политике заменяется ступенью выше); `sonnet` даёт `claude-sonnet-5-5`; границы версий sonnet 2.1.284 и opus 2.1.280 взяты из документации и на других версиях не проверялись; токены и цена Codex движком не записываются (учёт расхода не реализован). Haiku-маршрут `author-claude` вживую не проверен (на CLI из PATH 2.1.286 он недоступен по версии; новее бинарники расширения VS Code). Экономия не измерена и не заявляется.

Изменения 1.1.0 в исполняемой логике — только установщик (`--core-only`, защита от отката версии, установка VERSION, строгие параметры), его тест и `scripts/manifest.py`; они проходят независимое ревью. Предыдущий пакет 1.0.0 содержал более ранний движок (0862098): клон 1.0.0 нельзя использовать для обновления.

Манифест package-manifest.json фиксирует контрольные суммы и git blob id всех файлов репозитория (по содержимому с LF).

Ограничения v1: ASCII-пути, NTFS, экспорт в новый каталог, максимум 300 МиБ и 20 000 файлов. Docker считается доверенной границей. Код кандидата в контейнере способен подделать результат раннера; зелёные проверки служат свидетельством вместе с независимым ревью. Сохраняется граница одного пользователя. Публикация кода не означает передачи входа в аккаунты или гарантии наличия конкретной модели в другом аккаунте.

Версия 1.5.0 (кандидат, требует собственной независимой приёмки вне движка): **экономия токенов и времени без изменения модели доверия**. (1) Учёт расхода: токены Codex из событий `codex exec --json` (`turn.completed.usage`: вход, из кэша, выход), причина каждого вызова в записи резерва (первый, продолжение, сбой прошлого вызова, красные проверки, FIX, неоднозначный отчёт, новый кандидат, неизвестно), `CR report` и `CR status --json`, токены по ролям и сервисам, перенос токенов и оценки по `--continues`, `start --estimate N` (не лимит, превышение только сообщается). (2) Codex-reviewer запускается так же герметично, как автор (`--ephemeral --ignore-rules --ignore-user-config`, отключённые инструменты, контроль событий) и отвечает JSON по схеме Claude-reviewer; ответ не по схеме — не PASS, без скрытого повтора; ответы вызовов прежних версий разбираются прежним текстовым разбором (формат определяется записью резерва). (3) Один автоповтор после паузы — только если вызов достоверно не начался (нет событий модели, 429/сеть, не квота). (4) Запрос ревью: неизменные блоки в начале (общий префикс кругов для кэша сервиса), diff с контекстом функции (`-W`, откат на узкий), MINOR не больше 3. (5) Вывод `review`/`cycle` сжатый (вердикт, открытые ID, путь к отчёту; `--verbose` — полностью). (6) SKILL.md сокращён до ядра (~6,5 тыс. символов вместо 39,6 тыс.), подробности — `skills/agentq/reference/*.md` по ссылке; движок называет файл справки при кодах 2 и 3. Экономия токенов не измерена на живых задачах: цифры даст `CR report` на сопоставимых прогонах.

Версия 1.5.1 (кандидат, требует независимой приёмки вне движка): исправления дефектов, найденных замером 1.5.0 на эталонном наборе (`docs/benchmarks/2026-11-11-baseline-1.5.0.md`). (A-2) Вердикт определяют только проверки движка и reviewer: `unmet_requirements` автора (например, «без инструментов невозможно запустить тесты») остаётся справкой в журнале и для reviewer, но PASS в FIX не превращает; FIX без единого замечания и без красных проверок невозможен (UNCERTAIN и повтор ревью того же SHA), автору без предмета исправления платный вызов не делается; в промпт Codex-автора добавлено «проверки запускает движок». (A-1) Единица без файлов, вызовов, вердикта и изменений в своей области (пустая `main` чисто серверной задачи) в приёмке `finish` не учитывается, пока в ней нет изменений. (A-3) После обрыва вызова и `--continues` первый вызов той же роли получает причину `cli_failure`, а `report` показывает оборванный вызов прежней задачи с пометкой «расход неизвестен». (A-4) Ревью после нового кандидата получает причину `new_candidate`. (A-5) Номер круга автора перенесён в конец промпта: общий префикс до файлов не зависит от круга. Кэш Codex в вызовах движка остаётся нулевым: без `--output-schema` кэш работает (проверено двумя вызовами), причина в режиме схемы, а не в порядке промпта.

## Источник изменений

Все изменения оркестратора вносятся здесь. Правки установленных копий в ~/.claude не считаются обновлением источника и затираются следующей установкой. Движок меняется только через отдельную приёмку (независимая процедура вне самого движка); изменения установщика и скриптов — через независимое ревью. Синхронизация ai-knowledge (`sync-skills`, `install-global`) пропускает файлы оркестратора по списку `scripts/orchestrator-owned.txt` в ai-knowledge.
