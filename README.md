# Orchestrator Codex + Claude Code — agentq 1.1.1

**Единственный источник оркестратора agentq**: движок, навык, роли, общие защищённые зоны и установщик развиваются и устанавливаются из этого репозитория на любом компьютере. База знаний ai-knowledge хранит только личные правила и контекст и не копирует, не обновляет и не откатывает эти файлы.

Установка принятого глобального /agentq. Claude Code — тимлид и автор бэкенда; Codex — автор фронтенда. Независимое ревью выполняет другой сервис, проверки идут в Docker.

## Требования

Целевая среда v1: Windows, NTFS, Git Bash. Нужны:
- Git и Python 3.9+ (команда py -3, python3 или python);
- установленные Codex CLI и Claude Code CLI с отдельным входом в аккаунты на этом компьютере;
- Docker Desktop с Linux-контейнерами; локальный образ проверок для каждого проекта.

Установка этого пакета не устанавливает сторонние программы, не переносит входы в аккаунты и не запускает модельные запросы. Доступ к закрытым проектам и их зависимости настраиваются на каждом компьютере отдельно.

## Установка

Открыть **Git Bash**:

```bash
git clone https://github.com/ivanermolenko61-commits/Orchestrator-Codex-Claude-code.git
cd Orchestrator-Codex-Claude-code
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Последняя команда должна вывести: «Установленные копии совпадают с репозиторием».

Если на компьютере уже есть личный `~/.claude/CLAUDE.md` и собственный `workflow/project-template.md` (например, из ai-knowledge), добавить `--core-only` в обе команды: тогда ставится только оркестратор, а личные инструкции не сравниваются и не перезаписываются.

```bash
bash scripts/install-global.sh --apply --core-only
bash scripts/install-global.sh --core-only
```

Установщик кладёт файлы в ~/.claude: навык agentq (вместе с файлом VERSION), общие правила, роли и agentsrules.py. Прежние версии изменяемых файлов, включая ~/.claude/CLAUDE.md, сохраняет в ~/.claude/backups/install-ДАТА-ВРЕМЯ/. Прочие файлы не удаляет. Для одного лишь просмотра отличий запускать без --apply.

После установки открыть **новую сессию Claude Code** в целевом проекте:

```text
/agentq <цель задачи>
```

Продолжение прерванной задачи: /agentq без аргументов.

## Готовность проекта

Из корня Git-проекта в Git Bash:

```bash
bash ~/.claude/skills/agentq/codex-review.sh route
```

Коды: 0 — глобальный маршрут готов; 10 — использовать собственный координатор проекта; 11 — не хватает окружения; 12 — старый проектный координатор. Команда показывает причину и не обращается к модели.

Настроить AGENTS.md по ~/.claude/workflow/project-template.md. Конфигурацию .agents/agentq.json закоммитить **до** начала задачи. Пример для проекта с pytest (образ должен уже содержать Python и зависимости этого проекта):

```json
{
  "checks": {
    "backend": [["python", "-m", "pytest", "-q", "-p", "no:cacheprovider"]]
  },
  "check_image": {"backend": "my-project-checks:1"},
  "check_timeout": 600
}
```

Для frontend добавить реальные команды и образ проекта. Не копировать чужие имена образов без их подготовки. Отсутствие Docker, образа или подходящих проверок — явный блокер, а не успешная приёмка.

Для рабочих копий по умолчанию используется C:/Projects/agent-worktrees. Другой путь можно задать переменной AQ_WORKTREES в окружении сессии. Для нестандартного размещения CLI предусмотрены CODEX_BIN и CLAUDE_BIN (см. движок). Пути проектов v1 должны быть ASCII.

## Проверки без моделей

После установки:

```bash
bash scripts/test-install-global.sh
py -3 skills/agentq/selftest.py
```

Selftest использует поддельные CLI и временные Git-проекты; живых модельных запросов нет. Он требует установленный ~/.claude/scripts/agentsrules.py и ищет его через домашний каталог пользователя. Для проверки без затрагивания рабочей установки создать пустой каталог `<home>`, задать `HOME`/`USERPROFILE` на него и `CLAUDE_HOME=<home>/.claude`, выполнить `install-global.sh --apply --core-only` и запустить установленный `selftest.py` (на 1.1.1: 270/270).

Целостность пакета проверяет `python scripts/manifest.py check` (она же входит в `test-install-global.sh`); после правки файлов — `python scripts/manifest.py write`. На среде с python3 вместо Windows launcher заменить py -3 на python3. Прогон на Linux не подтверждает совместимость экспорта с файловыми системами за пределами NTFS.

## Обновление и восстановление

```bash
git pull --ff-only
bash scripts/install-global.sh --apply
bash scripts/install-global.sh
```

Затем открыть новую сессию Claude Code. Установленную версию показывает `cat ~/.claude/skills/agentq/VERSION`. Если установленная версия новее версии клона, установщик отказывает (код 2) и ничего не меняет: сначала обновить клон. Осознанный откат: `AQ_ALLOW_DOWNGRADE=1`. При расхождении истории Git остановиться и разобраться с локальными изменениями; не использовать reset/clean для автоматического обновления.

Для восстановления брать нужные прежние файлы из указанной установщиком папки backups и возвращать их по тем же относительным путям внутри ~/.claude. Переустановка не переносит состояние задач: оно остаётся в .ai целевого проекта на исходном компьютере.

## Что включено и что не переносится

Включены движок, selftest, точка входа, SKILL.md, общие защищённые зоны, три описания ролей, шаблон карточки проекта, установщик и скрипт манифеста. Движок, его selftest и точка входа перенесены из принятого выпуска без изменения байтов (git blob id зафиксированы в `package-manifest.json`, раздел provenance). В SKILL.md изменены только две ссылки на файлы ai-knowledge.

Не включены личная база знаний, .ai, журналы запросов, токены, учётные данные, .env, проектные базы и Docker-образы. Глобальный CLAUDE.md и шаблон проекта в этом пакете — общие инструкции без локальной базы знаний владельца. После установки можно добавить собственные инструкции; проверка установщика покажет отличие от пакета.

## Происхождение и границы приёмки

Версия 1.1.0 содержит выпуск agentq из ai-knowledge, коммит 1171344235498ce6aae7a891d5d8867bce2636b1. Независимая приёмка движка: PASS на 9aca6cc (Codex gpt-6.1-sol high, вне движка); между 9aca6cc и 1171344 менялся только SKILL.md, исполняемый код идентичен. Самопроверка выпуска: 258/258 офлайн. Принятый неизменённый движок повторно на модельное ревью не отправляется.

Версия 1.1.1 меняет учёт бюджета: расход принадлежит конкретной задаче плана (цепочке `start`/`--continues`). Следующая задача после принятой начинается с нуля; незавершённую можно продолжить через `--continues` и после того, как владелец запустил другую самостоятельную задачу (`--new-work`), — прежде возвращение начиналось бы с нуля. Правило описано в SKILL.md («Область бюджета») и global/CLAUDE.md. Движок и selftest в 1.1.1 отличаются от принятого 9aca6cc (provenance: unchanged_from_source=false) и требуют собственной независимой приёмки; самопроверка 270/270.

Изменения 1.1.0 в исполняемой логике — только установщик (`--core-only`, защита от отката версии, установка VERSION, строгие параметры), его тест и `scripts/manifest.py`; они проходят независимое ревью. Предыдущий пакет 1.0.0 содержал более ранний движок (0862098): клон 1.0.0 нельзя использовать для обновления.

Манифест package-manifest.json фиксирует контрольные суммы и git blob id всех файлов репозитория (по содержимому с LF).

Ограничения v1: ASCII-пути, NTFS, экспорт в новый каталог, максимум 300 МиБ и 20 000 файлов. Docker считается доверенной границей. Код кандидата в контейнере способен подделать результат раннера; зелёные проверки служат свидетельством вместе с независимым ревью. Сохраняется граница одного пользователя. Публикация кода не означает передачи входа в аккаунты или гарантии наличия конкретной модели в другом аккаунте.

## Источник изменений

Все изменения оркестратора вносятся здесь. Правки установленных копий в ~/.claude не считаются обновлением источника и затираются следующей установкой. Движок меняется только через отдельную приёмку (независимая процедура вне самого движка); изменения установщика и скриптов — через независимое ревью. Синхронизация ai-knowledge (`sync-skills`, `install-global`) пропускает файлы оркестратора по списку `scripts/orchestrator-owned.txt` в ai-knowledge.
