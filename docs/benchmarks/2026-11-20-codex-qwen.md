На одинаковых исходных файлах и спецификациях: `slug` (Codex → Qwen) и `clamp` (Qwen → Codex), обе реализации на Python. Каждая единица включает реализацию и тесты. Это одна пара прогонов, не статистическая оценка экономии. В последовательном прогоне Codex ошибся в ожидаемом числе дефисов собственного теста: проверки остановили ревью, автор исправил тест, затем Qwen принял. Разница расхода и времени включает этот дополнительный круг, прогрев кэша и вариативность сервисов; её нельзя целиком приписывать параллельности. Независимые контрольные утверждения ловят ошибки split/пустого ввода/Unicode и границ clamp, включая ValueError при инвертированных границах. Они не доказывают отсутствие всех возможных дефектов.

Отдельно проверен прямой тимлид: start → Codex непосредственно коммитит неполную slug → Qwen FIX с F1/F2 → прямое исправление и тесты → Qwen PASS, оба ID закрыты → finish VERIFIED. Два вызова Qwen, **ноль** фоновых вызовов автора. После смены lead назначения main остались Codex → Qwen. Финальный повтор на логике 1f1e769: Codex после исправления выполнил checks, Qwen из нового режима координатора отправил тот же SHA на независимое Qwen review и завершил VERIFIED. Два вызова Qwen, вход 3866 / выход 2780 (кэш 1024), ноль фоновых вызовов автора; F1/F2 закрыты.

Сценарии CLI не заменяют приёмку самого движка. Сам движок принимается отдельным Qwen-процессом вне agentq на точном коммите; результат фиксируется отдельно. Автоматическое восстановление после неопределённого сетевого обрыва живьём не провоцировалось: это покрывается офлайн-тестами receipts/таймаутов/бюджета, без повторной оплаты.

После внешнего FIX исправлен выбор проверок: теперь категория дополняется фактическими классами изменённых файлов из доверенной базы. Повторный параллельный прогон: 35,98 с циклы, 43,97 с с интеграцией и итоговой проверкой, 4 вызова. Codex: вход 36 069 / выход 649; Qwen: вход 3 262 / выход 1 300. Обе единицы интегрированы, полный итог VERIFIED; у frontend-единицы на Python реально выполнены backend и frontend suites. Этот повтор подтверждает исправление покрытия, прежнюю таблицу не заменяет.

Прямая реализация закреплена за автором единицы: после смены lead новый координатор делегирует ему. Для передачи координации автор выполняет checks после коммита; другой чат отправляет на независимое review тот же SHA. Новый SHA требует новой авторской фиксации. Это исключает саморевью при сохранении назначений. Status/интеграция/завершение доступны новому координатору. Повторный стенд использует отдельный AQ_WORKTREES под output-root: одинаковые имена задач прежних стендов иначе сталкиваются с существующими копиями и безопасно останавливаются до вызовов моделей.

Источники интерфейса CLI: [Qwen headless](https://qwenlm.github.io/qwen-code-docs/en/users/features/headless/), [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode). Фактические flags и события дополнительно проверены на установленных CLI. Для Qwen safe-mode недостаточно config.tools.core/exclude: явные CLI-запреты канонических имён и проверка init допускают только служебный structured_output и пустой MCP. Wildcard `*` не убрал инструменты; `--workflow-mode off` конфликтовал с safe-mode. Служебный ответ модели находится в structured_result.
